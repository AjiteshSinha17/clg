# Database Structure Documentation

This document outlines the 3 main Firestore collections used in the application.

## Overview

The application uses **3 primary collections** in Firestore:

1. **`users`** - User accounts and profiles
2. **`roommate_profiles`** - Roommate finder profiles
3. **`community_content`** - Community shared content (notes, PDFs, images)

---

## 1. Users Collection (`users`)

**Purpose:** Store user accounts for users who create an ID or login back to the app.

**Document ID:** User's UID (from Firebase Authentication)

**Fields:**
```typescript
{
  uid: string                    // User's unique ID
  email: string                  // User's email address
  name: string                   // User's display name
  avatarUrl: string              // Profile picture URL
  bannerUrl: string              // Profile banner URL
  bio: string                    // User bio/description
  
  // Academic Info
  college: string                // College name
  branch: string                 // Branch/department
  year: string                   // Academic year
  gender: string                 // User's gender
  
  // Verification
  verificationStatus: string     // "not_verified" | "pending" | "verified"
  collegeIdImageUrl: string       // URL to college ID image
  
  // Roommate Preferences (optional)
  isLookingForRoommate: boolean
  city: string
  area: string
  budgetMin: number
  budgetMax: number
  interestTags: string[]
  sleepSchedule: string          // "early" | "late" | "flexible"
  cleanlinessLevel: number       // 1-5
  smoking: string                // "no" | "occasionally" | "yes"
  drinking: string               // "no" | "occasionally" | "yes"
  livesAlone: boolean
  preferredGender: string        // "any" | "male" | "female"
  
  // Status
  profileCompleted: boolean
  isActive: boolean
  
  // Timestamps
  createdAt: Timestamp
  updatedAt: Timestamp
  lastLoginAt: Timestamp
}
```

**Usage:**
- Created when user registers
- Updated when user logs in (updates `lastLoginAt`)
- Used for authentication and profile management

**Service:** `lib/services/user_service.dart`
**Model:** `lib/models/user.dart`

---

## 2. Roommate Profiles Collection (`roommate_profiles`)

**Purpose:** Store profiles of users who are looking for roommates.

**Document ID:** User's UID (one profile per user)

**Fields:**
```typescript
{
  userId: string                 // Reference to user's UID
  
  // Profile Details
  bio: string                    // Roommate profile description
  city: string                   // City location
  area: string                   // Area/neighborhood
  budgetMin: number              // Minimum budget
  budgetMax: number              // Maximum budget
  interestTags: string[]         // Interests and hobbies
  sleepSchedule: string          // "early" | "late" | "flexible"
  cleanlinessLevel: number       // 1-5 scale
  smoking: string                // "no" | "occasionally" | "yes"
  drinking: string               // "no" | "occasionally" | "yes"
  livesAlone: boolean            // Current living situation
  lookingForRoommate: boolean    // Actively looking
  preferredGender: string        // "male" | "female" | "any"
  
  // Denormalized User Data (for performance)
  userName: string
  userCollege: string
  userAvatarUrl: string
  userVerificationStatus: string
  userGender: string
  
  // Timestamps
  createdAt: Timestamp
  updatedAt: Timestamp
}
```

**Usage:**
- Created when user sets up roommate profile
- Used for roommate matching and discovery
- Contains denormalized user data for faster queries

**Service:** `lib/services/roommate_service.dart`
**Model:** `lib/models/roommate_profile.dart`

---

## 3. Community Content Collection (`community_content`)

**Purpose:** Store uploaded files, PDFs, notes, and images shared in the community and people sections.

**Document ID:** Auto-generated by Firestore

**Fields:**
```typescript
{
  // Author Info
  authorId: string               // User's UID who uploaded
  authorName: string             // Author's display name
  authorAvatarUrl: string       // Author's avatar URL
  
  // Content Details
  title: string                 // Content title
  description: string            // Optional description
  contentType: string            // "note" | "pdf" | "image" | "mixed"
  
  // File URLs
  fileUrls: string[]             // Array of file URLs (PDFs, images, etc.)
  thumbnailUrl: string           // Optional thumbnail/preview image
  
  // Metadata
  category: string               // e.g., "study_notes", "lecture_slides", "resources"
  tags: string[]                 // Searchable tags
  subject: string                // Subject/course name
  college: string                // College name
  branch: string                 // Branch/department
  
  // Engagement Metrics
  downloadCount: number          // Number of downloads
  viewCount: number              // Number of views
  likeCount: number              // Number of likes
  likedBy: string[]              // Array of user IDs who liked
  
  // Status Flags
  isPublic: boolean              // Public visibility
  isApproved: boolean            // Moderation flag
  isActive: boolean              // Soft delete flag
  
  // Timestamps
  createdAt: Timestamp
  updatedAt: Timestamp
}
```

**Usage:**
- Created when users upload notes, PDFs, or images to community
- Supports multiple file types (PDFs, images, documents)
- Includes engagement tracking (views, downloads, likes)
- Supports categorization and tagging for searchability

**Service:** `lib/services/community_content_service.dart`
**Model:** `lib/models/community_content.dart`
**Provider:** `lib/state/community_content_provider.dart`

**Storage Paths:**
- PDFs: `community_content/pdfs/{userId}/{filename}`
- Images: `community_content/images/{userId}/{filename}`
- Other files: `community_content/files/{userId}/{filename}`

## Security Rules

All collections have security rules defined in `firestore.rules`:

- **Users:** Authenticated users can read any profile, but only update their own
- **Roommate Profiles:** Authenticated users can read all, but only create/update their own
- **Community Content:** Authenticated users can read public/approved content, but only create/update their own

---

## Best Practices

1. **User Collection:**
   - Always update `lastLoginAt` when user logs in
   - Use soft delete (`isActive: false`) instead of hard delete
   - Keep user data synchronized with Firebase Auth

2. **Roommate Profiles:**
   - Denormalize user data for better query performance
   - Update profile when user's verification status changes
   - Use composite indexes for complex queries

3. **Community Content:**
   - Always validate file types before upload
   - Implement moderation (`isApproved` flag)
   - Track engagement metrics for analytics
   - Use tags and categories for better searchability

---

## Indexes Required

You may need to create composite indexes in Firestore for:

1. **Roommate Profiles:**
   - `city` + `area` + `userVerificationStatus`
   - `interestTags` + `city`

2. **Community Content:**
   - `category` + `createdAt`
   - `subject` + `college` + `createdAt`
   - `tags` + `isActive` + `createdAt`

Create these indexes in the Firebase Console under Firestore > Indexes.
